# Sneakora — магазин кроссовок Nike · Adidas · Puma

Сайт магазина обуви с админкой. Покупатель выбирает модель и размер, кладёт в корзину и оформляет заказ: заказ сохраняется в админке, а покупатель отправляет его вам в Telegram готовым текстом.

- Языки: русский (`/`) и узбекский (`/uz`)
- Главные разделы — бренды (настраиваются в админке), внутри: Мужчинам / Женщинам / Детям
- Каталог с фильтрами: бренд, пол, размер EU, цвет, цена, скидки, новинки
- Админка `/admin`: заказы, товары (расцветки, фото, остатки по размерам), бренды, баннеры, настройки

> ⚠️ Сейчас на сайте **временный контент** с официальных сайтов Nike, Adidas и Puma (фото, видео, логотипы). Это товарные знаки брендов, а фото подгружаются прямо с их серверов и могут перестать открываться в любой момент. До публичного запуска замените их своими материалами (см. «Замена временного контента»).

## Технологии

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · PostgreSQL + Prisma 7 · next-intl · Docker + Caddy (HTTPS)

## Запуск на своём компьютере

Нужен Node.js 22+ (проверено на 24). Docker и отдельная установка PostgreSQL не нужны.

```bash
npm install
npm run db            # встроенный PostgreSQL (оставьте окно открытым)
```

Во втором окне терминала:

```bash
cp .env.example .env  # только при первом запуске, затем заполните значения (см. ниже)
npm run db:migrate    # создать таблицы
npm run db:seed       # наполнить временным контентом
npm run dev           # сайт: http://localhost:3000, админка: http://localhost:3000/admin
```

Для локального `.env`:

```
DATABASE_URL="postgresql://sneakora:sneakora@localhost:5433/sneakora"
SITE_URL="http://localhost:3000"
ADMIN_PASSWORD="любой пароль"
AUTH_SECRET="случайная строка от 32 символов"
UPLOAD_DIR="./uploads"
```

Полезные команды: `npm run db:studio` — просмотр базы в браузере, `npm run lint`, `npm run typecheck`, `npm run build`.

## Админка

Вход: `/admin`, пароль — `ADMIN_PASSWORD` из `.env`.

| Раздел | Что делает |
|---|---|
| Дашборд | Новые заказы, последние заказы, напоминание указать Telegram |
| Заказы | Список со статусами и поиском. В карточке заказа — состав, контакты, смена статуса, заметка |
| Товары | Бренд, пол, цена и скидка, описание RU/UZ, расцветки с фото и остатками по размерам EU |
| Бренды | Название, логотип, баннер (фото или видео), порядок в меню, вкл/выкл. Новый бренд сразу появляется в меню сайта |
| Баннеры | Слайдер вверху главной и промо-блок (фото или видео, тексты RU/UZ, кнопка) |
| Настройки | **Telegram для заказов**, телефон, Instagram, адрес, промо-полоса, текст «Доставка и оплата» |

Первым делом укажите в «Настройках» Telegram username, куда покупатели будут отправлять заказы.

Особенности:
- Размеры: пустое поле — размера нет в продаже, `0` — закончился (показывается зачёркнутым).
- «Унисекс» — товар показывается и у мужчин, и у женщин.
- Остатки **не списываются** автоматически при заказе: после подтверждения заказа поправьте остатки в карточке товара.
- Удалённый товар не пропадает из старых заказов (состав заказа хранится копией).

## Как работает оформление заказа

1. Покупатель в корзине вводит имя, телефон, комментарий.
2. Сервер заново проверяет цены и наличие, создаёт заказ (номера с 1001) и открывает страницу заказа.
3. На странице заказа кнопка «Отправить заказ в Telegram» открывает чат с вашим аккаунтом с готовым текстом (номер, товары, размеры, сумма, контакты). Есть кнопка «Скопировать текст» на случай, если Telegram не подставит текст.
4. Заказ сразу виден в админке со статусом «Новый».

## Деплой на VPS (Docker)

Подойдёт любой VPS с Ubuntu 22.04+, 2 ГБ RAM и Docker.

1. Направьте домен (A-запись `sneakora.uz` и `www.sneakora.uz`) на IP сервера.
2. Установите Docker: `curl -fsSL https://get.docker.com | sh`.
3. Скопируйте проект на сервер и создайте `.env` по образцу `.env.example`:
   ```bash
   cp .env.example .env
   nano .env   # DOMAIN, SITE_URL, POSTGRES_PASSWORD, ADMIN_PASSWORD, AUTH_SECRET
   ```
4. Запустите:
   ```bash
   docker compose up -d --build
   docker compose run --rm migrate npx prisma db seed   # только если нужен временный контент
   ```

Caddy сам получит HTTPS-сертификат. Что запускается: `db` (PostgreSQL), `migrate` (применяет миграции и завершается), `app` (сайт), `caddy` (HTTPS и раздача загруженных файлов).

Обновление после изменений в коде: `docker compose up -d --build`.

Резервная копия базы:
```bash
docker compose exec db pg_dump -U sneakora sneakora > backup-$(date +%F).sql
```
Загруженные фото лежат в Docker-томе `uploads` — его тоже стоит бэкапить.

## Замена временного контента

- **Логотип магазина**: положите файл в `public/logo/` и укажите путь в `SITE.logoSrc` в `src/lib/site.ts`. Пока там текстовый логотип «SNEAKORA».
- **Цвета и шрифты**: токены в `src/app/globals.css` (`--color-*`), шрифты в `src/app/fonts.ts`.
- **Бренды, баннеры, товары**: через админку. Загружайте свои фото и видео, временные удаляйте.
- **Иконка вкладки**: `src/app/icon.svg`.
- Начать с чистой базы: удалите товары, бренды и баннеры в админке или используйте пустую базу без `db:seed`.

## Точки расширения

Код заранее подготовлен к следующим функциям. Добавляются без переделки остального:

| Что | Где |
|---|---|
| Telegram-бот, который присылает каждый новый заказ в ваш чат | Уже написан: задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env` (`src/lib/notify/`) |
| Онлайн-оплата (Click, Payme, Uzum) | Новый провайдер в `src/lib/payments/`, в заказе уже есть `paymentMethod` и `paymentStatus` |
| Личные кабинеты покупателей | В заказе есть `customerId`; корзина и избранное — `src/stores/` |
| Отдельные аккаунты сотрудников с ролями | Таблица `AdminUser` уже есть; поменять только `checkCredentials` в `src/lib/auth/admin.ts` |
| Хранение фото в S3/CDN | Новый `StorageProvider` в `src/lib/storage/` |
| Английский язык | Добавить `en` в `src/i18n/routing.ts` и файл `src/messages/en.json` |

Как подключить бота: создайте бота у [@BotFather](https://t.me/BotFather), добавьте его в нужный чат или группу, узнайте `chat_id` (например, через `https://api.telegram.org/bot<TOKEN>/getUpdates`) и пропишите оба значения в `.env`.

## Кэширование

Страницы читают базу на каждый запрос (`dynamic = "force-dynamic"`, `cacheComponents: false` в `next.config.ts`). Поэтому изменения из админки видны сразу, а Docker-образ собирается без доступа к базе. Для небольшого магазина этого достаточно. Если трафик вырастет, можно включить Cache Components (`"use cache"` + `revalidateTag` в действиях админки).

## Структура

```
prisma/              схема БД, миграции, временный контент (seed)
src/app/[locale]/    страницы магазина (главная, /w каталог, /brand/…, /t/… товар, корзина, заказ)
src/app/admin/       админка
src/app/api/         заказы, проверка корзины, загрузка файлов
src/components/      компоненты магазина (shop), админки (admin), общие (ui)
src/lib/             БД, каталог, заказы, авторизация, хранилище, уведомления, оплата
src/messages/        тексты RU/UZ
src/proxy.ts         языки в адресах + защита /admin
```
